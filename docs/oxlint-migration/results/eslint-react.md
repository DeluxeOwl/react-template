# eslint-react migration evidence

Written by the orchestrator. The investigation agent stopped before writing its summary. Its logs are the other
`eslint-react-*` files in this folder. Per-rule rows are in `eslint-react.json`.

## Verdict

- **62 migrate-port**, **4 keep-eslint**, **0 migrate-native**, **0 blocked**. That covers all 66 `@eslint-react/*` rules the
  web preset enables (`recommended-typescript` plus our explicit `no-leaked-conditional-rendering`).
- None of the 66 has an active native oxlint twin. The agent proposed two native mappings
  (`jsx-no-comment-textnodes` → `react/jsx-no-comment-textnodes`, `jsx-no-namespace` → `react/no-namespace`). I
  vendored them with the rest instead, so the plugin has one implementation (same reasoning as Vitest, D-017).
- Seven rules are declared fixable but only ever offer suggestions: `exhaustive-deps`, `jsx-no-children-prop`,
  `jsx-no-children-prop-with-children`, `jsx-no-leaked-dollar`, `no-context-provider`, `no-forward-ref`,
  `no-use-context`. They pass under the suggestion-only policy: at least one diagnostic, and 0 files changed by
  `--fix` on both sides. The agent's run also compared the suggestion contents, and they matched.

## Vendored copy

`packages/lint/vendor/eslint-react/` is generated by `scratch/oxlint-migration/vendor/specs/eslint-react.ts` with the
new `packages` layout. The plugin is spread over 13 packages (`@eslint-react/{eslint-plugin,ast,core,eslint,jsx,shared,var}`
and `eslint-plugin-react-{x,dom,jsx,naming-convention,rsc,web-api}`, all 5.7.1). Each gets a folder with its LICENSE,
and the imports between them are rewritten to relative paths. 14 files, 640 KB. Patches:

- 8 files import `ESLintUtils`/`ASTUtils` from the `@typescript-eslint/utils` root, which loads ESLint. They now
  import from the `/eslint-utils` and `/ast-utils` subpaths.
- Three places read the decoded `value` of JSX text or attribute strings: the attribute resolver in `@eslint-react/jsx`,
  `no-leaked-dollar`, and `getFullyQualifiedName`. oxc leaves HTML entities encoded (F-013), so they now decode with
  `_compat/jsx-entities.js`. Before this patch, `jsx-no-leaked-dollar` missed 2 of 10 diagnostics, `dom-no-script-url`
  missed 4 of 39, and `dom-no-unsafe-iframe-sandbox` missed 1 of 22, all on entity cases (`&#36;`, `&#45;`, `&#32;`).

External runtime dependencies: `@typescript-eslint/{scope-manager,type-utils,types,typescript-estree,utils}`, `birecord`,
`compare-versions`, `string-ts`, `ts-api-utils`, `ts-pattern`, `typescript`, `zod`. The plugin loads in about 370 ms
cold, because it loads TypeScript.

## Keep in ESLint

| Rule                                                       | Why                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `no-leaked-conditional-rendering`                          | Reads types from the TypeScript checker (`parserServices`), which oxlint JS plugins don't get. Typed parity in the investigation: ESLint 15, oxlint 0.                                                                                                                                                                            |
| `dom-no-hydrate`, `dom-no-render`, `dom-no-use-form-state` | Their fix inserts an import. With competing fixes in one file this can produce a duplicate import binding, which typescript-estree accepts and oxc rejects. oxlint then stops fixing the file while ESLint goes on: 5/6 changed files identical for `dom-no-render`. Same reason `vitest/prefer-importing-vitest-globals` stayed. |

## Integration notes

- ESLint's `recommended-typescript` sets `settings["react-x"] = { version: "detect", importSource: "react", polymorphicPropName: "as" }`.
  The harness passed these to oxlint, so the oxlint React preset must set them too.
- ESLint turns off six of these rules for generated UI (`createVendoredConfig` in `packages/lint/src/react.ts`):
  `dom-no-dangerously-set-innerhtml`, `no-array-index-key`, `no-context-provider`, `no-nested-component-definitions`,
  `set-state-in-effect`, `use-state`. They need to move to oxlint's vendored-files override.
- No source comment names an `@eslint-react` rule.
- `@eslint-react/eslint-plugin` stays an ESLint dependency for the four kept rules.

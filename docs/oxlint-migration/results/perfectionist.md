# Perfectionist migration — investigation in progress

Inventory verified: 21 rules, all fixable, no native candidates. Includes `sort-variable-declarations`; excludes `sort-modules`.

Upstream: `eslint-plugin-perfectionist@5.9.0`, MIT, cloned tag `v5.9.0` (commit `fafddd677c784b692ff6335b3ffa31a8283b0901`) into `scratch/oxlint-migration/upstream/perfectionist`.

## Harness requests (urgent, reproductions)

1. **Vendor import closure misses multiline imports.** `vendor/vendor.ts:111-118` anchors imports to a single line (`[^\n]*?`). Perfectionist uses `import {\n...\n} from './...js'` throughout its dist. `devbox run -- bun scratch/oxlint-migration/vendor/vendor.ts perfectionist` copies 178 files, then `devbox run -- bun scratch/oxlint-migration/harness/parity.ts perfectionist/sort-imports --impl port` fails plugin loading on every file: missing `packages/lint/vendor/perfectionist/rules/sort-variable-declarations/types.js` imported by `rules/sort-variable-declarations.js:19-23`. This is a tool artefact, not a runtime/AST failure. The closure must parse multiline static imports/reexports (and detect bare dependencies there too).
2. **Harvester lacks perfectionist's tester API.** `devbox run -- bun scratch/oxlint-migration/harness/harvest.ts perfectionist/sort-variable-declarations scratch/oxlint-migration/upstream/perfectionist/test/rules/sort-variable-declarations.test.ts` reports `0 snippets → 0 cases`. Tests import `createRuleTester` (`eslint-vitest-rule-tester`) which returns `valid`/`invalid` functions called with individual cases; tagged templates use `dedent`. `buildOxlintRuleTester(rule)` returns `.run(name, {valid, invalid})`. All currently become the no-op `anything` proxy. Needed shim: `dedent = unindent`; `createRuleTester() = {valid: collectCase, invalid: collectCase}`; `buildOxlintRuleTester() = {run: (_, tests) => collectTests(tests)}`. Async callbacks must complete before collected snippets are written (tests contain many sequential awaits).
3. **License discovery misses lowercase `license.md`.** Upstream `eslint-plugin-perfectionist/license.md` contains the full MIT notice but `vendor/vendor.ts:265` checks only `LICENSE`, `LICENSE.md`, `license`. Temporary local spec patch preserves the full notice in copied `utils/create-eslint-rule.js`; generator should also copy `license.md` to `LICENSE`. Remove that workaround once supported.

## New runtime finding — mixed disable/enable semantics

**Proposed F-xxx:** oxlint 1.86's directive engine only pairs bare disable with bare enable, and rule-specific disable with matching rule-specific enable. A rule-specific `/* eslint-disable plugin/rule */` followed by bare `/* eslint-enable */` remains disabled through EOF, unlike ESLint. Minimal generic JS plugin (`/tmp/perfectionist-directive-demo.mjs`, config `.json`, input `.ts`) reports `VariableDeclarator` nodes: `before` is reported, `disabled` is suppressed, **`after` is wrongly suppressed**. Same-name explicit enable and bare-disable/bare-enable controls report `before` and `after` correctly. This is not a perfectionist implementation bug. It blocks strict directive parity until oxlint is fixed or a generic suppression adapter is agreed. No repo directives currently name perfectionist (`git grep` returned none).

Real rule reproduction: `bun harness/parity.ts perfectionist/sort-classes --impl upstream --files focused-directive- --corpus cases --show 8 --keep`, 5 ESLint / 4 oxlint diagnostics, 4/5 fixed files identical; case `harness/cases/perfectionist__sort-classes/apps/web/__parity__/focused-directive-0277.tsx:4` disables the rule and `:8` bare-enables. ESLint moves `a` to the top; oxlint changes nothing. Normalized directive copies preserve original harvested files; `/tmp/perfectionist-write-directive-cases.ts` writes 97 additional cases by changing only comment-token tester namespaces. `harness/reports/batch-perfectionist-upstream-directives.json`: 18 FAIL (one mixed-enable case each, decorators/heritage several target nodes), `sort-array-includes` PASS non-vacuously, `sort-objects` PASS vacuously (its existing upstream namespace cases all suppress), `sort-switch-case` has no directive cases.
